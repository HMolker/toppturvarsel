# v5.1 plan: weather on the route, GPX in and out

**Built in v5.1.0** (see CHANGELOG): `src/sources/metno.js`, `src/weather.js`,
`public/terrain/weather.js` and `public/terrain/gpx.js`. Kept as the record
of what was planned. One change from the plan: the forecast uses MET's
`complete` product rather than `compact`, because only it carries wind gusts.

## 1. Weather at the start and the highest point

**Where it shows:** the "Weather on the route" box in the route panel
(`public/terrain/app.js`, `renderPanel`), which already names the two points
and their heights. `analyse()` returns them as `weatherPoints.start` and
`weatherPoints.summit` (`public/terrain/analysis.js`).

**Source:** MET Norway's Locationforecast 2.0 (the data behind yr.no), free,
no key:

    GET https://api.met.no/weatherapi/locationforecast/2.0/compact?lat=61.0539&lon=8.2143&altitude=1920

- `altitude` in whole metres. Pass the route's own height for each point:
  MET corrects the temperature to it, which is the whole point of asking for
  the summit separately.
- At most 4 decimals in lat/lon (more is refused and defeats their cache).
- An identifying User-Agent is required: `src/util/ua.js` already has one.
- Honour `Expires` and send `If-Modified-Since`; a 304 costs nothing.
  Terms: https://api.met.no/doc/TermsOfService (credit "MET Norway").
- Check all of the above against the live API and its docs before writing
  the parser, as every other source in this project was.

**Server:** `POST /api/terrain/weather {"points": [[lat, lon, ele], ...]}`,
at most 2 points, both inside the service area (`pointAllowed` in
`src/tiles.js`, the same rule as `/api/terrain/profile`). Cache per point
rounded to 3 decimals and 10 m, until the `Expires` MET sent. Put the fetch
in `src/sources/metno.js` next to `forecast.js` (Open-Meteo stays for the
planner).

**Page:** hour by hour for today and tomorrow, both points side by side:
temperature, wind and gusts, cloud, precipitation and snow. Reuse the hour
strip style from the tour forecast (`public/route.js`). Set
`FEATURES.weather = true` in `public/terrain/routeio.js`.

## 2. GPX import

The **Import GPX** button is in the route toolbar, disabled by
`FEATURES.gpxImport`. On click: a file picker for `.gpx`, parse in the
browser (the tour editor's parser in `editor/tour-editor.html`, or a port of
`parseGpx` in `src/util/gpx.js`: tracks first, then routes, then
waypoints), thin the track to at most 150 points the way "Use as my route"
thins a tour's track (`simplify` in `public/terrain/suggest.js` on Web
Mercator pixels at z16), then `S.route = ...; changed()`. Nothing is
uploaded; the file stays in the browser. This covers Garmin: export the
activity from Garmin Connect as GPX.

## 3. GPX export

**Export GPX** (`FEATURES.gpxExport`): a `<trk>` with the route's points,
`<ele>` from the measured profile where a sample falls on a vertex (samples
carry `v`, the vertex index), the route name as `<name>`, no timestamps.
Download as `<slugified name>.gpx`. Optionally a `<rte>` too, for watches
that navigate routes rather than tracks.

## Route model

`public/terrain/routeio.js`: `{ v: 1, name, points: [[lat, lon], ...] }`,
in the address bar as an encoded polyline and in this browser's saved list.
GPX in and out are translations of this shape; nothing else needs to change.
